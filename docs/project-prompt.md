# YouDu — контекст проекта

Документ для быстрого ввода в курс дела: человека или ИИ-ассистента. Описывает
оба репозитория, общий транзакционный процесс и те договорённости, нарушение
которых ломает вещи тихо.

Актуально на 19 сентября 2026.

---

## Что это за проект

YouDu — маркетплейс бытовых и профессиональных услуг в ОАЭ, прежде всего в Дубае.
Заказчик публикует задание, специалисты откликаются со своей ценой, заказчик
выбирает одного, работа выполняется, стороны обмениваются отзывами.

Сайт: `https://youdu.ae`. Интерфейс русскоязычный.

Платформа построена на Sharetribe Flex. Это означает, что часть логики живёт не в
коде, а в конфигурации на стороне Sharetribe: транзакционный процесс, письма
процесса, настройки листингов. Деплой на Heroku обновляет только наш код —
изменения процесса выкатываются отдельно через `flex-cli`.

## Два репозитория

| Репозиторий | Назначение |
|---|---|
| [YouDu-ae/youduae](https://github.com/YouDu-ae/youduae) | Веб-сайт и весь серверный API. Локально `~/web-template` |
| [YouDu-ae/YouDuMobile](https://github.com/YouDu-ae/YouDuMobile) | iOS-приложение на React Native. Локально `~/YouDuMobile` |

Мобильное приложение не имеет собственного бэкенда: оно ходит в тот же Heroku-сервер,
что и сайт, плюс напрямую в Sharetribe Flex API. Поэтому серверные правки в `youduae`
затрагивают оба продукта, и обратной совместимостью эндпоинтов пренебрегать нельзя.

Рабочая ветка в обоих репозиториях — `main`.

## Критично: роли инвертированы

Это главный источник ошибок в проекте. Словарь Sharetribe в YouDu вывернут наизнанку:

| В терминах YouDu | В терминах Sharetribe | Что делает |
|---|---|---|
| Заказчик, автор задания | **provider** | Владеет листингом-заданием, выбирает исполнителя, завершает работу |
| Специалист, исполнитель | **customer** | Откликается на задание, выполняет работу |

Причина в том, что заданием владеет тот, кто его опубликовал, а в Sharetribe
владелец листинга — это provider.

Последствия, о которых нужно помнить постоянно:

- Отзыв о специалисте — это `ofCustomer`. Отзыв о заказчике — `ofProvider`.
- Фильтр транзакций специалиста — `customerId`, заказчика — `providerId`.
- Переходы `accept-offer`, `decline-offer`, `complete` имеет право делать
  **provider**, то есть заказчик.
- Мобильное приложение — приложение **заказчика**: `APP_ROLE = 'provider'`
  в `src/constants/appRole.ts`. Специалисты приложением не пользуются вовсе,
  они работают через сайт.

Не пишите роли строками по месту. В `server/api-util/reputation.js` есть
константы `ROLE`, `REVIEW_TYPE_BY_ROLE` и `TRANSACTION_FILTER_BY_ROLE` —
пользуйтесь ими.

## Транзакционный процесс assignment-flow-v3

Определение: `ext/transaction-processes/assignment-flow-v3/process.edn`.
Используемый алиас: `assignment-flow-v3/release-1` (задан в `src/config/configListing.js`).

Состояния и переходы:

```
                  inquire (customer = специалист)
                        ↓
                    inquiry ──── decline-offer (provider) ──→ declined ⊗
                        │
                  accept-offer (provider, privileged)
                        ↓
                    accepted
                        │
                    complete (provider, privileged)
                        ↓
                   completed ──── P7D без отзывов ──→ reviewed ⊗
                     │     │
       review-1-by-provider review-1-by-customer
                     ↓     ↓
      reviewed-by-provider reviewed-by-customer
                     │     │
       review-2-by-customer review-2-by-provider
                     └──┬──┘
                        ↓
                    reviewed ⊗
```

Что важно знать про этот процесс:

- **Операторских переходов нет вообще.** Никаких `transition/operator-*`.
  Попытка выполнить такой переход через Integration API всегда провалится.
- **Из `inquiry` нет выхода по таймеру.** Отклик живёт, пока его не примут или
  не отклонят. Поэтому при найме исполнителя сервер сам закрывает остальные
  отклики — см. `server/api-util/declineCompetingOffers.js`.
- **Окно отзыва — семь дней** от входа в `completed`, после чего сделка уходит
  в `reviewed` сама.
- **Выбор перехода отзыва зависит от состояния.** Если вторая сторона ещё не
  писала отзыв — `review-1-by-*`, если уже написала — `review-2-by-*`.
- Задание закрывается при найме: у листинга ставится `publicData.hired = true`.
  Исполнитель на задание всегда один.

Список переходов, означающих «работа выполнена», определён один раз в
`server/api-util/assignmentState.js` (`COMPLETED_OR_BEYOND`). Он включает три
перехода истечения окна отзыва: задание, по которому никто не успел написать
отзыв, всё равно было выполнено. Не заводите собственную копию этого списка.

## Веб: youduae

Форк официального Sharetribe Web Template, версия 8.8.0. React 18, Redux,
react-intl, серверный рендеринг через Express. Node 18–22.

Команды: `yarn dev`, `yarn test`, `yarn test-server`, `yarn build`.

### Серверная часть

`server/` содержит около сорока собственных эндпоинтов поверх шаблона.
Наиболее значимые группы:

- **Транзакции.** `initiate-privileged.js` (отклик), `transition-privileged.js`
  (переходы с сайта), `accept-offer.js`, `decline-offer.js`,
  `complete-transaction.js`. Последние три — мобильные, с авторизацией по
  Bearer-токену через `api-util/mobileSdk.js`.
- **Репутация и статистика.** `api-util/reputation.js` — единственное место, где
  выводится публичная репутация. `platform-stats.js`, `user-reviews-stats.js`,
  `area-stats.js`.
- **Поиск специалистов.** `search-executors.js`, `category-specialists.js`.
  Видимость специалиста в категории зависит от заполненного `serviceCategories`
  в профиле.
- **Telegram.** `telegram-bot.js` — уведомления и админ-команды,
  `telegram-blog-webhook.js`, `sync-telegram-categories.js`.
- **Блог и поддержка.** `blog-admin.js`, `blog-articles.js`, `support-tickets.js`.
- **Напоминания.** `server/reminders/` — почасовой обход прямо в веб-дино
  (`timer.js`, подключён в `server/index.js`). Ищет неотвеченные отклики и шлёт
  дайджесты специалистам. Отправляет **только в Telegram**, push не подключён.

Своя база PostgreSQL (`server/db/`) для того, чего нет в Sharetribe: блог
(`blog_articles`, `blog_categories`, `blog_pending_posts`), тикеты поддержки,
подписчики Telegram, журнал напоминаний (`reminder_log`), человекочитаемые
номера заданий (`listing_id_mapping`).

Помощники, которые стоит использовать вместо самописного кода:
`api-util/paginate.js` (`queryAllPages`, `queryTotalItems` — Sharetribe отдаёт
максимум 100 строк на страницу), `api-util/cache.js`, `api-util/sdk.js`.

### Клиентская часть

`src/containers/` — помимо шаблонных страниц есть собственные: `LandingPage`,
`CooperationPage`, `BaraholkaPage`, `BlogPage`/`BlogArticlePage`/`BlogAdminPage`,
`CategoryExecutorsPage`, `GuestListingWizard`, `PostFromDraftPage`,
`SupportPage`, `VerificationPage`, `TopbarCustom`, `FooterCustom`.

Категории услуг синхронизированы с мобильным приложением — при изменении правьте
оба места.

## Мобильное приложение: YouDuMobile

React Native 0.76.9, bare (не Expo), TypeScript strict. Около 17 тысяч строк в
`src/`. Навигация — React Navigation 7. Состояние — только React, ни Redux, ни
React Query. Локализации нет: все строки русские, прямо в JSX.

Только iOS. Под Android отсутствует `google-services.json`, то есть push там
не настроен. Приложение **ещё не опубликовано в App Store**.

### Устройство

- `src/services/sharetribe.ts` — сердце приложения, singleton. Два бэкенда:
  Sharetribe Flex API напрямую и наш Heroku API. Токены в AsyncStorage,
  проактивное и реактивное обновление, дедупликация обновлений.
- `src/services/notifications.ts` — FCM, регистрация токена устройства.
- `src/navigation/AppNavigator.tsx` — пять нижних вкладок, у каждой свой стек;
  общие экраны регистрируются в каждом стеке.
- `src/theme/index.ts` — дизайн-токены. Часть экранов ещё импортирует цвета из
  `src/config/api.ts` — это legacy.
- `src/utils/transactionStatus.ts` — сопоставление переходов с русскими
  статусами. Содержит только те переходы, которые реально есть в процессе.
- Компонентов всего шесть. Типовых `Input`, `Card`, `Avatar`, `Modal`
  не существует, каждый экран рисует свой заголовок и свои стили.

### Известное состояние

В репозитории заметный объём мёртвого кода: экраны исполнителя от прошлой версии
приложения и старые шаги мастера создания задания. Они не зарегистрированы в
навигаторе. Перед удалением проверяйте, что дубликат действительно не
используется — у нескольких экранов есть почти одноимённые живые версии.

Ирина Гросс планирует заменить UI на новый дизайн. При этом нельзя потерять
кнопку «Отклонить» в `OffersScreen` и честную обработку ошибок завершения
задания — это механика процесса, а не оформление.

## Инфраструктура и деплой

- **Heroku**, приложение `youdu`. Деплой: `git push heroku main` из `~/web-template`.
  Сборка занимает около трёх с половиной минут.
- **Sharetribe Console** — настройки маркетплейса, встроенные письма, категории.
  Меняется руками, в коде не отражается.
- **flex-cli** — выкатка транзакционного процесса и его писем. Отдельно от
  Heroku: `flex-cli process push`, затем `update-alias`. Письма процесса
  отправляет Sharetribe, а не наш сервер.
- **Plausible** — аналитика, подключена через Sharetribe Console.
  Google Analytics не используется.

После деплоя имеет смысл проверить, что живой именно новый код: например,
`POST /api/decline-offer` без токена должен отдавать 401 с текстом
`Bearer token is missing`.

## Память проекта

Долговременная память ведётся в Graphiti поверх Neo4j Aura. Правила — в
`.cursor/rules/graphiti-memory.mdc` обоих репозиториев. Коротко: читать нужно из
**обеих** групп `youdu` и `youdo_project`, писать — только в `youdu`.

Обслуживание вынесено в `~/graphiti-ops/graphiti_ops.py` (вне репозиториев):
ежедневный `ping` не даёт бесплатному инстансу Aura уснуть, еженедельный
`export` кладёт копию в `~/graphiti-ops/backups`. Инстанс, простоявший на паузе
30 дней, удаляется — поэтому пинг важен.

## Ловушки

Вещи, на которых уже обжигались.

**Роли.** См. раздел выше. Самая частая и самая тихая ошибка.

**Несуществующие переходы.** В коде время от времени заводились ссылки на
`transition/operator-*`, `transition/request-payment`, `transition/confirm-payment`.
Ни одного из них в процессе нет. Сверяйтесь с `process.edn`.

**Ошибка, выданная за успех.** Эндпоинт завершения сделки когда-то превращал
ошибку недопустимого перехода в `success: true`, из-за чего приложение считало
работу завершённой, хотя ничего не произошло. Не подменяйте отказ успехом; если
операция идемпотентна, проверяйте состояние явно.

**Страницы Sharetribe.** `perPage` максимум 100. Запрос без чтения
`meta.totalPages` молча теряет всё остальное. Используйте `queryAllPages`.

**Спекулятивные переходы.** `transition-privileged.js` умеет выполнять
предварительный расчёт. Побочные действия должны быть закрыты проверкой
`!isSpeculative`, иначе расчёт натворит настоящих изменений.

**Публичные страницы Telegram.** На `t.me` ссылками становятся только
`@упоминания`; обычный URL остаётся плоским текстом. Закреплённые сообщения
краулеру не видны.

**Чужие объявления.** Тексты объявлений из Telegram-групп нельзя переносить на
сайт: они принадлежат авторам, права администратора согласием не являются.
